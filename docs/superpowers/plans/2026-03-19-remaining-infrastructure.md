### Task 1: ECOD Homology Pair Density Distributions (~2h)

**Context:** Reviewer asked for density distributions computed only on ECOD homology pairs (cf. "Contrastive learning unites sequence and structure..."). Currently distance distributions include all pairs; filtering to known homologs shows whether pLMs capture structural similarity within homologous families.

**Files:**
- Create: `src/data_preparation/ecod_homology_pairs.py`

- [ ] Parse ECOD domain file (already downloaded by `download_reference_data.sh` → `data/reference/ecod/ecod.latest.domains.txt`)
- [ ] Map ECOD domains to UniProt IDs (ECOD provides this mapping)
- [ ] For each ECOD hierarchy level (T/H/X/F group), filter protein pairs to same-group pairs
- [ ] Compute embedding distance distributions per group level using KDE
- [ ] Output: filtered parquet + matplotlib density plots (one per pLM, overlaid by ECOD level)
- [ ] CLI: `--pairs_parquet`, `--ecod_domains`, `--distance_columns`, `--output_dir`

### Task 2: Per-Residue Feature Probes (~3h)

**Context:** Week 3 task — "Explore per-residue pLM features: binding sites, pathogenicity predictions." Need a lightweight probe training script that tests whether per-residue embeddings encode specific biological features.

**Files:**
- Create: `src/training/residue_probes.py`
- Create: `src/data_preparation/residue_probe_data.py`

- [ ] `residue_probe_data.py`: fetch binding site annotations from UniProt (FT BINDING, FT ACT_SITE) and pathogenicity labels (ClinVar or UniProt FT VARIANT)
- [ ] Format: H5 with per-residue labels aligned to embedding sequences
- [ ] `residue_probes.py`: train a simple linear probe (logistic regression or 1-layer MLP) on per-residue embeddings
- [ ] Requires per-residue embeddings (generated with `--embedding_type per_residue`), not per-protein
- [ ] Evaluate: per-residue accuracy, F1, AUROC for each probe task per pLM
- [ ] Output: summary table (parquet) + per-pLM comparison plots
- [ ] CLI: `--embeddings_dir`, `--labels_h5`, `--output_dir`, `--probe_type {linear,mlp}`

**Note:** This task depends on having per-residue embeddings, which aren't generated by default. The embedding_generation.py script supports `--embedding_type per_residue` already. Tobias would need to re-run embedding generation with this flag for the models of interest.

### Task 3: Binding-Site Alignment Recovery (~2h)

**Context:** "Test whether binding-site alignment can be recovered from embeddings (à la Steinegger & Schütze's aligner)." Given two homologous proteins with known binding sites, can per-residue embedding cosine similarity recover the correct residue alignment?

**Files:**
- Create: `src/evaluation/binding_site_alignment.py`

- [ ] Load per-residue embeddings for protein pairs
- [ ] For pairs with known binding sites (from UniProt FT BINDING), compute per-residue cosine similarity matrix
- [ ] Extract alignment by greedy or Hungarian matching on the similarity matrix
- [ ] Compare recovered alignment against structural alignment (from TM-align or known PDB alignments)
- [ ] Metrics: alignment accuracy, binding-site recovery rate (% of binding residues correctly aligned)
- [ ] CLI: `--embeddings_h5`, `--binding_sites_tsv`, `--output_dir`

**Note:** Also depends on per-residue embeddings. Can be developed and tested on a small subset.

### Task 4: Overtraining Investigation (~2h)

**Context:** "Investigate whether some pLMs are overtrained (similar to PP2 issues)." Check if certain pLMs show signs of memorizing training data — manifested as unusually tight distance distributions or train/val divergence.

**Files:**
- Create: `src/evaluation/overtraining_analysis.py`

- [ ] Load training logs from wandb or tensorboard (parse `models/` directory for run artifacts)
- [ ] For each pLM embedding × model type × target param:
  - Extract train_loss and val_loss trajectories
  - Compute final train/val gap (larger gap = more overfit)
  - Flag runs where val_loss increases while train_loss decreases
- [ ] Cross-pLM comparison: for pLMs that produce similar embedding dims, compare whether larger models overfit more
- [ ] Check distance distribution kurtosis — overtrained models may produce overly peaked distributions
- [ ] Output: summary table + train/val divergence plots
- [ ] CLI: `--models_dir`, `--output_dir`
